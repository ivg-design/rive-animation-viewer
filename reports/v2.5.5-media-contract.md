# Media contract, implementation handoff

The host controller owns source/session validation and capture. Native jobs own
bounded frame storage and encoders. The app retains its normal UI during recording.

All native calls use a `request` object. Fields inside it are snake_case.

```text
media_export_capabilities({}) -> { formats: [{id, extension, alpha, animated,
  available, reason?}], encoders: [...], limits: {...}, gif: {...} }
media_export_begin({request: {format, width, height, fps: {numerator,denominator},
  output_path?, overwrite:false, alpha:false, background:'#000000', quality:80,
  gif?:{encoder:'auto'|'gifski'|'ffmpeg',quality?,motion_quality?,lossy_quality?,
       repeat:0,max_bytes?,size_policy?:'quality_only'|'quality_fps_scale'},
  source_identity?, source_session?, capture_codec?, max_frames? /* obsolete */}}) -> Job
media_export_frame({request:{job_id,frame_index,png_base64}}) -> Job
media_export_finish({request:{job_id,frame_count}}) -> Job
media_export_cancel({request:{job_id}}) -> Job
media_export_abort({request:{job_id,error}}) -> Job // internal failure; retain accepted capture
media_export_status({request:{job_id}}) -> Job

Job = {job_id,state,stage,received_frames,frame_count?,bytes_spooled?,output_path?,
  actual_bytes?,warnings:[],error?,progress?,resolved_settings?}
state = capturing | encoding | completed | cancelled | failed
```

`finish` starts background encoding and returns immediately. Static formats need
one frame. The native PNG adapter retains compatibility for sparse indexes,
where gaps/last-frame padding hold preceding pixels. The desktop recording clock
now submits consecutive frames and drains its sealed stop interval; it does not
rely on sparse-index holds. Native limits bound memory and image pixels; disk
space governs recording lifetime. Never expose
frame base64 in results. Cancellation removes incomplete outputs and frame spools.

Live recording probes WebCodecs for opaque h264/hevc/vp9. Supported configurations
encode on capture and send bounded binary packets directly from the owning render
WebView through `/__rav-media/{native-job-id}/{packet-index}`. The native route
checks the current render label and job session before writing. Packets contain a
u32LE record count, followed by u32LE byte lengths and encoded access units. AVC/
HEVC use Annex B with explicit access-unit delimiters; VP9 is wrapped in IVF.
Native finish remuxes without re-encoding, establishes CFR timestamps, and then
fully decodes/validates output. No arbitrary file path is accepted by the route.

A renderer failure uses the internal main-webview-only abort command. It retains
acknowledged capture data, bounded error text and a recovery descriptor; terminal
native receipts remain visible through host status. Explicit user cancellation
uses immediate renderer disposal plus native cleanup. Abort can interrupt a
queued graceful stop without waiting for encoder drain and is capture-ID scoped.
Graceful stop watches lack of frame progress rather than recording duration.
Host stop returns its job immediately. During draining, advancing frame, encoded
frame or acknowledged-packet counters renew a 60-second command inactivity
deadline; unchanged heartbeats cannot renew it. Native idle expiry retains data.
Image preparation is cancellable before decoding, with immediate disposal of
previous images and safe disposal of late decoder results.
`rav_step_frames` is rejected while recording owns advancement.

PNG fallback uses three worker slots and the same binary route, one raw PNG per
indexed request. Slots are released after native disk receipt, with capture-order
delivery. Stop drains all pending writes. PNG gap indexes may hold earlier images;
encoded streams require every presentation record and never add native holds.
The video writer rejects missing indexes/count mismatch instead of synthesizing
holds. `capture_receipt.repeated_frames` is zero on successful contiguous video
submission. The host also exposes `capture_clock` (fixed-step mode, maximum lag,
and active current lag in milliseconds); this is required to distinguish full
simulation sampling from keeping up with live wall time.

There are no product time/frame/spool/output-size caps. u32 indexes remain a
technical storage ceiling; image/FPS/memory/stall limits remain. Before writing,
free space must cover existing spool + twice the incoming bytes + 128 MiB. A
nonempty low-space capture seals its accepted prefix; finish must use the returned
count. Finishing can consume the reserve down to 8 MiB. Unexpected disk failure
retains accepted capture for recovery. This is not an OS-level reservation.

Host public service methods: `capabilities()`, `exportMedia(options)`,
`startRecording(options)`, `stopRecording()`, `status(jobId?)`, `cancel(jobId?)`,
`stepFrames(options)`, `pointer(options)`. `exportMedia`/`startRecording` return
an asynchronous host job ID; status merges capture and native encoding results.
All UI and MCP operations call this service. Options use snake_case at the public
boundary too; format IDs are h264,h265,webm,apng,gif,png,jpg,webp.

Export options: `mode:'timeline'|'still'`, `start_seconds`, `end_seconds`,
`at_seconds`, optional `start_frame`/`end_frame` (end exclusive), output `width`,
`height`, `scale`, `fps` (number or rational), `alpha`, `background`, `quality`,
`cursor`, `gif_preset:'source'|'balanced'|'small'|'custom'|'target-size'`, plus
native path/GIF options. Record options include `duration_seconds` (omit for manual)
and the same encoding controls, plus an optional recording-clock `interactions`
schedule. All eight MCP handlers enforce their raw schemas before service lookup.
A static still is valid in either playback mode.

Limits/presets: Small longest edge 480, FPS<=12; Balanced 960,FPS<=20; neither
upscales. At most 5 target-size attempts. Capability-specific settings must reject
unsupported values. Both source and rational frame timing are recorded in receipt.

The renderer exclusively owns advancement during recording: frame zero uses
zero delta; later frames use denominator/numerator seconds. Native wake-ups and
queued browser callbacks route to the same pump. At most four frames/eight ms of
work is done per batch before yielding. Scheduled actions run against each frame
boundary, before drawing, with a tiny float-round-trip tolerance. Capacity is
checked before both action application and advancement. Stop restores normal
playback ownership. No source file may exceed 400 lines.

The visible capture canvas and the encoded output have separate resolution
contracts. The canvas backing store must cover the displayed CSS size multiplied
by the device pixel ratio, even when the requested output is smaller. Capture
composition then samples that surface into the exact requested output dimensions.
Stopping or failing restores the normal live-preview dimensions. Output sizing
must never make the on-screen preview appear enlarged or pixelated.
