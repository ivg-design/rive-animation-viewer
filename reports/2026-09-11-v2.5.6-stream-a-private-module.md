# 2.5.6 Stream A — separately distributed file-inspection module

Status: implemented locally; CI configuration values pending (owner action). 2026-09-11.

## Why

The repository is public and its release workflow builds on GitHub Actions from `main`.
The 2.5.6 tree replaced runtime-based inspection with a parse-once inspection module that
must not be published as source. Committing the tree as it stood would have published it;
omitting it would have broken CI.

## What changed

| Area | Change |
| --- | --- |
| `src/app/rive/inspection/parser-client.js` (new, tracked) | Loader: dynamically imports `./private/client.js`; when absent, every inspection rejects with `This build does not include the file inspection module.` (`InspectionUnavailableError`). `reset`/`dispose` are safe before load. |
| `src/app/rive/inspection/service.js` | Imports the loader instead of the module. |
| `src/app/rive/inspection/private/` (gitignored) | `client.js`, `worker.js`, `metadata.js`, `metadata.shared.js`, `manifest.json` — staged by the script. Internal names and user-facing strings neutralized ("File inspection …"). |
| `vendor/inspection/` (gitignored) | `parser.js`, `parser.wasm`, `LICENSE` (neutral names; the worker's `locateFile` maps the wasm). |
| `tests/unit/rive/inspection/` | Public `service.test.js` now uses `fixtures/inspection-metadata.json` (normalized schema only); `parser-client.test.js` covers the loader (4 tests). | `scripts/private-modules.mjs` (new) | `pack`, `stage`, `acquire`, `verify`, `strip`. Bundle = zip with `manifest.json` (per-file sha256). Extraction falls back unzip → tar → 7z for Windows runners. |

| `.gitignore` | The three staged paths. |

| `Documentation/ideas/` | Parser name scrubbed from three idea docs; the decompiler idea moved to `~/.rav-private/ideas/`. |

## Proof

- Stripped tree (`private-modules.mjs strip`): `npm test` → 127 files, 1,468 tests passed;
  `npm run build` produced `dist/` with only `parser-client.js`, `service.js`,
  `source-scope.js` under inspection and no `vendor/inspection`.
- Staged tree: `verify` OK; `npm run build` copies `private/` and `vendor/inspection/` into
  `dist/`; inspection suites 5 files / 28 tests passed.
- Name gate: case-insensitive grep for the parser's name over the tree (excluding the staged
  private paths and vendored eruda, which contains the substring by coincidence) → empty.
- Packaged DEV app (`npm run build:dev`, build b0237-20260911-1242-50ebd63-dirty): launched with
  `RAV_DEV_SCRIPT_ACCESS=1`, `rav_open_file` teachers-pet.riv → `ok:true`; `rav_get_artboards`
  returned 18 artboards and `rav_get_vm_tree` the STAGE_VM inputs — both come from the
  parse-once metadata, so the dynamic import of `private/client.js` and the worker's
  `vendor/inspection/parser.*` URLs resolve inside the embedded `dist-dev`. No inspection
  errors in the app log. The module-absent path is covered by the loader unit tests only
  (a stripped packaged build was not made).

   `RAV_PRIVATE_MODULES_SHA256` = the sha256 above.

## Addendum 2026-09-15 — module rebuilt on RF Parser 2.5.14

Everything above this line is the original 2026-09-11 report and is kept
intact as historical record (bundle `file-inspection-2.5.6.zip`, sha256
`6cf7377ebedbcab3ec6042318f33492e9bca556e2513fe15a7d7b09d2e0640ea`, is no
longer what the candidate ships).

The candidate's staged private module was rebuilt against **RF Parser
2.5.14** on 2026-09-14 (see `RUN_ROOT/downstream/rav/report.md` sections 5-6
for the decisive experiment and re-vendor). The 2.5.6 module's core-object
type registry could not deserialize two runtime-v0.1.384 fixtures
(`instance_value_binds.riv`, `semantic/zero_area_semantics.riv`), failing with
`Error initializing runtime instance` (a WASM `call_indirect` fault) before
the actual `@rive-app` runtime was ever reached; the 2.5.14 module opens both
cleanly (14/14 fixtures pass on both renderers post-rebuild).

**Current values (supersede every occurrence of the 2.5.6 bundle/sha above):**

- Bundle: `~/.rav-private/modules/file-inspection-2.5.14.zip` (identical bytes
  to `RUN_ROOT/release/rav/rav-private-modules-rfp-2.5.14.zip` — verified by
  `shasum -a 256`, both files).
- sha256: `811bac6a96c7af9c13f417f6c0d2a153888eb851058cee206f81fd661d32a4fa`
- `RAV_PRIVATE_MODULES_SHA256` **must** be this value.

exact failure this addendum's rebuild fixed. As of this addendum, neither
variable exists yet on `rive-animation-viewer` (confirmed via read-only

section 6) — first-time configuration must use the 2.5.14 bundle/sha above,
not the 2.5.6 ones this original report's "Owner actions" section names.
`RUN_ROOT/downstream/rav/report.md` section 8 carries the concrete,

**Addendum 2026-09-18 — asset_image kind-alias regression fixed, bundle re-packed.**

The 2026-09-14 rebuild above (module bytes: RF Parser 2.5.14) exposed a
latent bug in the module's own (private, gitignored) normalizer wrapper: RF
Parser 2.5.14 reports image/asset ViewModel properties with the raw kind
string `asset_image` (2.5.6 used `asset`), and
`src/app/rive/inspection/private/metadata.shared.js`'s `KIND_ALIASES` table
had no entry for it, so every image property was silently dropped from the
normalized ViewModel map — caught by the isolated-DEV MCP acceptance harness
failing on `data_binding_images_test.riv`
(`rav_vm_set_image: Image property "sub_1_im" not found or not writable`).
Fixed by adding `asset_image: 'image'` to `KIND_ALIASES`
(`RUN_ROOT/downstream/rav/report.md` section 13 has the full root-cause A/B
evidence, fix, tests, and live re-verification). `vendor/inspection/parser.{js,wasm}`
themselves are unchanged — still the identical RF Parser 2.5.14 binary pair
described above.

**Current values (supersede every occurrence of the 2.5.14 bundle/sha above):**

- Bundle: `~/.rav-private/modules/file-inspection-2.5.14.zip` (identical
  bytes to `RUN_ROOT/release/rav/rav-private-modules-rfp-2.5.14-fix1.zip` —
  verified by `shasum -a 256`, both files). The pre-fix bundle is preserved
  at `~/.rav-private/modules/file-inspection-2.5.14-pre-asset_image-fix.zip`.
- sha256: `3520b411061839992166cd8a18a86f59ff3b9b437c19d6e5f46e8713e157c35a`
- `RAV_PRIVATE_MODULES_SHA256` **must** be this value, not the 2026-09-14
  addendum's `811bac6a...`.
- `RAV_PRIVATE_MODULES_URL` **must** point at this re-packed 2.5.14 asset.

Neither `RAV_PRIVATE_MODULES_URL` nor `RAV_PRIVATE_MODULES_SHA256` exists yet
on `rive-animation-viewer` as of this addendum (unchanged from 2026-09-14) —
first-time configuration must use the sha256 above.
