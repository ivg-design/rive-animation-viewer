## Product contract

The release combines the verified TrackMap fixes with timeline export, interactive
state-machine recording, and still-image export. All operations are available
from **EXPORT** and through MCP. Existing snippet and standalone-HTML export
remain separate options and must not regress. Media output contains the animation,
with an optional composited pointer, rather than the application controls/chrome.

| Source | Required behavior |
| --- | --- |
| Timeline | Export one authored timeline duration or a selected segment, with times or frames, independent of real-time rendering speed. |
| State machine | Record the current live session; manual Start/Stop, an app shortcut, or a specified duration. Capture the visible consequences of direct pointer interaction, VM edits, triggers, and MCP actions. |
| Still | PNG/JPG/WebP of the current timeline or state-machine frame; support a requested timeline time/frame without altering the user's live session. |

| Output | Baseline support and transparency |
| --- | --- |
| H.264 / MP4 | Opaque; explicit background/matte. No misleading alpha option. |
| H.265 / MP4 | Opaque baseline. HEVC-with-alpha is a distinct platform capability and is not implied by ordinary HEVC encoding. |
| WebM / VP9 | Opaque or alpha; decoded alpha must be tested, not inferred from a container flag. |
| APNG | Full alpha or background; animated duration and repeat settings. |
| GIF | Palette-based animation; binary transparency or matte, never full alpha. |
| PNG | Lossless still, alpha or background. |
| JPG | Still, quality and matte, no alpha. |
| WebP | Still, lossy/lossless quality options and alpha. |

Interpretation of the requested video alpha option: WebM must support both modes;
do not advertise unsupported H.264/HEVC alpha. Platform-specific HEVC-alpha can be
evaluated without delaying the required cross-platform WebM-alpha path.

Export settings include source, range/duration, output dimensions, aspect lock,
frame rate where relevant, format/quality, background/alpha, cursor visibility,
repeat where meaningful, output location, progress, cancellation, and failure
details. Source file/runtime/VM target are pinned for a job. A save chooser is a UI
convenience; agents can supply a path without interacting with dialogs.

## GIF size controls

Use one preset resolver shared by UI and MCP. Proposed starting presets, to be
tuned against the real animation corpus:

| Preset | Dimensions | FPS | Quality intent |
| --- | --- | --- | --- |
| Source | Explicit source size; do not accept an encoder's implicit resize | Source rate within supported GIF timing, with warnings when needed | High |
| Balanced | Long edge at most 960 px, never upscale | At most 20 | Initial quality 80 |
| Small | Long edge at most 480 px, never upscale | At most 12 | Initial quality 60 |
| Custom | Exact aspect-locked dimensions or 100/75/50/25% scale | User-selected supported rate | Individual supported settings |
| Target size | Explicit byte limit and allowed quality/dimension/FPS floors | Preserved duration | Bounded search, at most 5 encodes initially |

- Changing FPS resamples presentation; it must not change playback speed or clip
  duration. GIF timing is quantized; report the actual resulting duration/rate.
- Controls: overall quality, supported motion/lossy quality, loop count, segment
  trimming, transparency/matte, and compact encoding of unchanged areas/frames
  where the selected encoder supports it. Loop metadata is not a promise of a
  smaller file. A faster encoding mode is not labeled a smaller-file mode.
- Advanced controls are capability-driven: do not show fictitious palette-size or
  dithering switches when the chosen encoder owns those decisions internally.
- Target size only changes settings the user permits. If the bound cannot be met,
  return the smallest achieved result and a clear unmet-target status; never
  silently shorten the recording. Estimated size and measured size are distinct.
- Preserve a bounded captured master long enough to retry GIF settings without
  rerunning state-machine interactions. No lossy-video-to-GIF intermediate.

Preferred GIF candidate: **gifski**. Its official CLI accepts PNG frames and offers
quality, motion/lossy quality, dimensions, FPS, and repeat controls. Explicitly
control output dimensions; do not inherit its default downscaling. Its native
timing limits and browser compatibility warnings belong in capability reporting.
[Official project](https://github.com/ImageOptim/gifski),
[CLI definitions](https://raw.githubusercontent.com/ImageOptim/gifski/main/src/bin/gifski.rs).

gifski is AGPL-3.0-or-later with alternative commercial licensing. Prefer an
encoder adapter and a separately packaged executable while evaluating compatible
distribution terms; a sidecar does not automatically remove licensing obligations.
Keep an FFmpeg GIF adapter as an explicit alternative, not a silent quality switch.
[gifski licensing](https://github.com/ImageOptim/gifski#license).

## Architecture and dependency gates

### A. Inspection and session correctness

- Inspection receives copied bytes and creates an independently owned file/Luau
  environment. No live `contents`, artboard, or state-machine instantiation for
  metadata, thumbnails, UI refreshes, MCP queries, or export setup.
- Return/cache immutable plain metadata by source identity and runtime version.
  Dispose owned resources on success, error, and cancellation. An unavailable
  inspection result must never trigger an unsafe live-player fallback.
- Extend existing source identity (file identity plus bytes hash) to all control
  snapshots and queued mutations, including artboard and VM target. Reject late
  messages from a prior load. Keep global/root/input namespaces distinct.
- Different files or changed bytes use authored defaults. Same-source renderer
  rebuilds preserve permitted state. Separate explicit user/MCP overrides from
  observed script-derived values; retain existing reset semantics deliberately.
- Fix this before declaring any media-export behavior trustworthy.

### B. Frame clock and capture

- One owner advances each playback/capture session. Timeline export uses an
  independently loaded source and explicit frame stepping, not screen recording
  or a loop over the existing screenshot MCP tool.
- Use an end-exclusive time range internally; convert UI inclusive frame ends
  explicitly. For scripts dependent on history, advance from the baseline through
  the segment start. Seeking alone is not a general simulation substitute.
- Preserve rational FPS such as 30000/1001. Define initialization, settling,
  advance, draw, and readback order once. Report frame-duration rounding.
- State-machine recording captures the actual authoritative session; input logs
  aid diagnostics but are not treated as a universally deterministic replay of
  arbitrary Luau, audio clocks, or random behavior.
- Timestamp captures with a monotonic clock. Bound the encoder queue. If capture
  misses real-time frames, preserve duration using timestamped holds and report
  misses; never describe generated holds as fully captured motion. Surface a
  warning or fail a strict recording instead of silently degrading it.
- Keep UI/VM controls and pointer interaction live while recording. Normalize
  pointer coordinates to exported canvas space/DPR and composite the pointer only
  when requested. The cursor must not accidentally include VM-panel chrome.
- Start/stop/shortcut and MCP use the same recording controller. Starting a
  recording from a current state does not implicitly reset the state machine.
- Background advancement and reset/capture completion must not depend on two
  visible-window RAF callbacks. Validate a desktop-controlled scheduling path
  while hidden/minimized; do not assume `setInterval` defeats WebView suspension.
  Expose effective advancement and explicit suspension/failure when the OS cannot
  execute the job. Avoid concurrent clocks and unbounded catch-up after resume.
- Screenshot safeguards currently downscale at 2 million pixels: media export
  needs its own explicit resolution contract, never silent diagnostic downscaling.

### C. Native media jobs

- Encode outside the UI/render thread. FFmpeg is the initial video/APNG/image
  engine candidate; gifski uses a dedicated GIF adapter.
- Discovery returns tested encoder capabilities; a locally installed Homebrew
  executable is development evidence, not a shipping dependency solution.
- Use a bounded lossless frame spool or equivalent streaming master; do not keep
  an entire long recording in JS memory. Fix resource limits before implementation.
- UUID jobs, validated dimensions/rates/formats, ordered timestamped frames,
  backpressure, progress, explicit overwrite policy, and cancellation. No shell
  interpolation or arbitrary encoder arguments via MCP.
- Write temporary files, verify the completed output, then atomically publish the
  final path. Clean abandoned jobs on cancellation, error, and next launch.
- Pin binary versions, checksums, build configuration and source provenance for
  each shipped architecture. Sign/notarize binaries as required. Include licenses
  and corresponding-source arrangements. FFmpeg's license depends on enabled
  components; avoid casually copying the development binary into a release.
  [FFmpeg licensing/build guidance](https://ffmpeg.org/legal.html).
- Distribution/capability validation is an early gate, not a release-day surprise.
  No private tooling dependency is introduced.

## Shared interfaces: freeze before UI/MCP fan-out

```text
SourceScope = sourceIdentity + runtimeKey + artboardKey + vmInstanceKey + sessionId
Inspection = plain artboard/timeline/SM/input metadata, duration/FPS or explicit unknown
MediaOptions = source/range/duration + format + size/FPS + alpha/matte/cursor + quality
Job = id + state + frame counts + elapsed/duration + progress + warnings + output receipt
States = preparing -> capturing/recording -> encoding -> verifying -> completed
Terminal alternatives = cancelled | failed
```

Proposed native commands: `media_export_capabilities`, `media_export_begin`,
`media_export_frame`, `media_export_finish`, `media_export_cancel`,
`media_export_status`. Frame transport is internal; MCP never relays all frames.
Final command payloads are frozen with the native owner before consumers are built.

Proposed public tools (same service as UI):

- `rav_media_capabilities`: formats, alpha, encoders, bounds and GIF controls.
- `rav_export_media`: timeline/range or still export; returns job ID immediately.
- `rav_record_start`: current state machine, duration or manual stop, options.
- `rav_record_stop`: finish the recording and encode; no ten-second blocking RPC.
- `rav_media_status` and `rav_media_cancel`: bounded job control/results.
- `rav_step_frames`: deterministic advancement/capture support for automation.
- Existing VM/trigger tools remain recording-aware; add typed pointer input if
  the current MCP surface cannot drive the same interactions as a physical pointer.

Both Node and native MCP registries, validators, instructions and discovery tests
must agree. Normal responses contain IDs/counts/status; hierarchy and images are
explicit queries. Rejected operations cannot masquerade as success.

## Acceptance and efficient verification

1. Reuse the saved TrackMap reproduction and a small deterministic timeline fixture;
   add an alpha-gradient/cursor/interaction fixture only where existing ones lack
   coverage. No broad .riv search or repeated full-repo rereads.
2. Fast per-lane unit/contract tests first. Run the full JS/Rust/architecture suite
   only after integration or a change that warrants it; do not run full builds in
   each worker. One coordinator owns the isolated desktop build.
3. Desktop cold starts, fresh filename, repeated inspection, A->B, changed bytes at
   same path, VM target changes, delayed commands, same-source rebuild, reset,
   hidden/minimized playback and deterministic step/capture must pass.
4. Decode every format. Check dimensions, first/last/intermediate frames, frame
   count, duration/rate tolerance, alpha over contrasting backgrounds, matte edges,
   and GIF disposal/loop behavior. Merely producing a file is not acceptance.
5. Record actual pointer hover/press/drag and VM edits/triggers, from UI and MCP;
   verify their visible effects occur at corresponding output times. Test cursor
   on/off, stop shortcut during editing, manual/timed stops and cancellation.
6. Exercise GIF source/balanced/small/custom/target-size. Verify no unintended
   upscale, hidden encoder resizing, speed change, or impossible size guarantee.
7. Stress bounded queues/disk, unwritable destinations, existing files, invalid
   combinations, missing/failed encoder, interrupted job, and application restart.
8. Preserve native timeline scrubbing, compact snippets, standalone HTML export and
   control selection. Export acceptance requires a **built desktop RAV app** and
   inspection/playback of the output artifact; the web viewer cannot close it.
9. Test macOS architectures and Windows according to the release matrix. Where a
   platform cannot be exercised locally, CI evidence is mandatory before claiming
   support. Keep runtime versions and encoder versions in every acceptance receipt.

Scope assumptions: visual media is requested; audio capture/muxing is not included
without a separate requirement. Output excludes application chrome. Capture/export
can be cancelled and cannot silently change the loaded file or user's live state.
