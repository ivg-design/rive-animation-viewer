## Regression found and fixed by C1

The acceptance harness failed at `images: open b` → `rav_vm_set_image sub_1/sub_1_im: Image
property not found`. Control on production 2.5.5: `rav_get_vm_tree` lists 4 paths
(`main_im`, `Number property`, `sub_2/sub_2_im`, `sub_1/sub_1_im`); the 2.5.6 build listed 1.
Cause: the parse-once inspection metadata reports image asset properties as `asset`, and
the normalizer only accepted `image`, so every image property — and every nested ViewModel
whose only property is an image — vanished from the tree. Fixed in the private module
(`asset`/`assetimage` → `image`; artboard properties remain a distinct, unsupported class),
private unit test added, bundle repacked (sha256
`6cf7377ebedbcab3ec6042318f33492e9bca556e2513fe15a7d7b09d2e0640ea`), app rebuilt.
After the fix the VM index for the fixture reads
`main: main_im/image, Number property/number, sub_2/viewmodel, sub_1/viewmodel · sub_1: sub_1_im/image · sub_2: sub_2_im/image`.
