# RAV 2.5.5 recording upgrade — 2026-09-03

Status: unreleased implementation on `codex/v2.5.5-media-export`, based on
`95eb566`. Desktop evidence below is from isolated macOS Apple silicon DEV and
WebGL2 2.42.0. Production, Launch Services and document associations were untouched.
This receipt supplements the [earlier implementation receipt](2026-09-03-v2.5.5-implementation-receipt.md).

## What changed and why

The earlier capture path compressed PNGs on the animation thread, relayed them
through host messages, and filled missed presentation samples with earlier images.
It could preserve duration while visibly losing motion. An initial 310-second
streaming test still synthesized 3,265 holds: faster encoding alone did not fix
clock ownership. That result is retained as a failed baseline, not counted as a
smooth-recording pass.

Recording now owns Rive advancement at the output rate. Each index advances once,
runs its scheduled interactions, draws and captures. Delayed wake-ups catch up
individual samples in bounded batches. Video rejects missing indexes rather than
padding, and manual stop seals and drains the exact requested interval. Native
wake-ups continue when browser RAF is suppressed.

Supported opaque H.264, HEVC and VP9 use WebCodecs with hardware acceleration
requested, stream bounded binary packets directly to native disk IO, and remux
rather than encode again after stopping. Capability probing happens in the actual
render WebView. Alpha, APNG and GIF use lossless PNG capture with three worker
slots. Their final encoding remains more expensive. Every published output is
fully decoded once and checked; successful packaging alone is insufficient.

Product limits on recording duration, frame count, temporary/output size and total
job time were removed. The spool index lives on disk. Free-space checks reserve
finalization headroom, and low-space capture seals the accepted portion. Bounded
queues, dimensions, memory and inactivity watchdogs remain necessary. Counts use
u32 storage; this is not an unlimited-integer file format.

Stop returns a job immediately, while the status bar displays capture draining,
finalization, verification and saving in RAV colors. Progress extends an inactivity
deadline only when rendered frames, encoded frames or acknowledged native packets
advance. Polling cannot keep an idle operation alive. Cancel interrupts a blocked
stop or image preparation; previously decoded and late image resources are
released. A cancelled stop cannot subsequently initiate finalization.

Renderer, transport and idle-watchdog failures preserve acknowledged native data
and expose a recovery descriptor instead of silently deleting it. Recovery repairs
an unacknowledged tail but never invents missing bytes. Explicit user cancellation
still cleans its spool. Status-lock contention waits rather than masquerading as
encoder backpressure.

The older b0203 scheduler could put floating-point boundary times one frame late.
The corrected scheduler's 600 one-per-frame operations used distinct matching
frame indexes; measured residual lateness was only floating-point noise
(approximately 1.8e-15s).

During minimize/restore in the long test, capture briefly lagged wall time by
649ms. It recovered every simulation sample without duplicated output. This is
not evidence of zero visible system stalls. Sustained GPU, disk or system overload
can delay live unscheduled inputs; no implementation can promise uninterrupted
60 FPS on arbitrary hardware. `capture_clock.lag_ms` and `max_lag_ms` make that
separate from saved-frame completeness. Hardware preference is not proof of
hardware encoding on every system.

## Failure and cancellation evidence

Desktop b0205:

- Frame stepping during recording was rejected without pausing playback; Cancel
  completed in 24ms and published no file.
- Injected renderer failure retained 30 accepted HEVC frames. Remux and strict
  decode recovered exactly those 30; no incomplete destination was published.
- Cancel interrupted a deliberately stalled stop in 49ms.
- Synchronous preparation failure cleared recording ownership; a subsequent
  two-second recording captured and decoded all 120 frames.

Final native harness: 35 unit tests passed (8 explicit real-tool tests ignored in that pass), plus four real-artifact streaming suites with FFmpeg/ffprobe.
Coverage includes accepted-prefix recovery for H.264/HEVC/VP9, low-space partial
finalization, shortened-source refusal, race-safe journal cleanup, idle expiry
retention, and concurrent status/upload admission. No actual system disk was
filled, and no association-mutating tests were run.

## MCP coverage

The generated desktop matrix contains 267 cases and covers all eight media tools in both MCP registries (57 total tools). On b0206 all 267 rows ran: 57 expected rejections, 72 mechanics passes, 122 mechanics passes still marked for case-specific visual review, 3 command passes, 12 fixture gaps and 1 real lifecycle failure. The run produced 190 artifacts (4,521,988 bytes); 112 recordings reported a fixed-step clock and none reported held frames. Maximum observed clock lag in the matrix was 199.67ms.

The lifecycle failure was not waived: replacing the source could leave the old job capturing until the idle watchdog if the renderer event was missed. Host status now compares the active source session on every poll and fails the old job immediately. A b0207 focused desktop retest completed in 3.72s; the final b0208 retest completed in 1.31s, reported the explicit source/playback-change error, retained 8 acknowledged frames for recovery and published no output. Test recovery spools were inspected and removed.

Every public media option and nested field was exercised or rejected at the raw schema boundary where a matching authored fixture existed. The 12 blocked rows are explicit fixture gaps: timed global boolean/enum/trigger/image/clear-image; scheduled list image/clear-image; and scheduled global boolean/enum/trigger/image/clear-image. No synthetic property was substituted, so those runtime bindings remain unclaimed. Sampled decoded outputs establish cursor inclusion/exclusion, absence of RAV chrome, root string/boolean changes, trigger response, image replacement/clear and alpha behavior. Rows still labelled visual review are not silently promoted to visual acceptance.

## Final build and remaining acceptance boundaries

Final desktop candidate: `b0208-20260903-1451-95eb566-dirty`, RAV 2.5.5 DEV, WebGL2 2.42.0, Apple silicon. Capability preflight advertised 57 tools, all eight media formats, and null product ceilings for duration, frame count, spool bytes, output bytes and job lifetime.

The full source gate passed: architecture budget for 372 files, dependency graph of 203 modules / 337 dependencies with no violations, 118 Vitest files / 1,385 tests, and 18 telemetry worker tests. The final package build completed unsigned with seven existing unused-code warnings.

The b0207 fault suite (same native sidecar digest as b0208) passed frame-step rejection plus 9ms cancellation, 30-frame renderer-prefix recovery with strict decode and no publication, 34ms cancellation of a stalled stop, preparation cleanup, and a fresh 120-frame recording afterward. A separate deliberately throttled drain returned from Stop in 1ms, remained in advancing `encoding/draining` state after 62.20s, then completed all 90 frames after 71.86s with no warnings. This proves progress can extend finalization beyond the former 60-second host command timeout; it is not an encoding-speed benchmark.

The status bar was directly observed during that drain with the centered TrackMap preview and RAV-colored `Finishing capture…` progress. The final low-resolution desktop retest was directly observed after the density fix and remained crisp. TrackMap was restored at the end to `TrackMapSM`, 481 paths, centered/contain, playing, with the saved control snapshot reapplied.

Production encoder redistribution/provenance/signing and Windows/Linux runtime
acceptance remain release gates. Local FFmpeg/gifski success does not approve
redistribution. This work does not publish 2.5.5, modify production or infer user
acceptance. The final DEV app is left available for inspection.
