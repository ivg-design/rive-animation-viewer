## Verdict

**Not release ready.** The automated suite and the real desktop media matrix pass, but one production distribution blocker and three confirmed runtime/product regressions remain. The current working tree is also an unreleased, intentionally dirty 2.5.5 implementation rather than a releasable commit.

## Confirmed findings

### 1. Release builds do not contain the encoders required by media export

**Severity: High — release blocker**

The DEV bundle succeeds because the exact DEV identifier is permitted to discover local Homebrew tools. Production only accepts a hash-verified `encoders/manifest.json` under the application resource directory. The production Tauri resource list currently contains only `RiveFileIcon.icns`; it does not package FFmpeg, ffprobe, gifski, or an encoder manifest.

Current live capabilities report `distribution.ready: false` and `review_required: true`. The source documentation also states that no binaries are bundled and that licensing, provenance, signing, and packaging review remain open.

Evidence:

- `src-tauri/src/app/support/media.rs:50-96`
- `src-tauri/src/app/media_export/discovery.rs:302-303`
- `src-tauri/tauri.conf.json:58-60`
- `src-tauri/src/app/media_export/README.md:109-117`

Impact: a clean production installation cannot provide the new media formats even though they work in this developer build.

Required closure: choose and document the redistribution model, package signed/notarized encoder resources plus the verified manifest, then run the complete export matrix from a production-identifier build on a clean machine with Homebrew/PATH encoders unavailable.

### 2. Default compact snippets still expand to every ViewModel property

**Severity: Medium — confirmed user-visible regression**

A cold launch followed by opening `trackmap_v7.5.riv` generated this default compact snippet without any user property selection:

- 481 concrete property accessors
- 520 lines
- 60,641 bytes

The same result persisted after the toolbar reset. RAV's “changed controls” selector considered all 105 reusable selectors changed, covering all 481 concrete list-expanded properties.

The generator itself behaves correctly when given an explicit selection: one selector produced one path, 40 lines, and 1,250 bytes, with no standalone UI chrome. Scaffold mode remains intentionally verbose. The regression is therefore in the default/changed selection baseline, not in accessor serialization.

Relevant code:

- `src/app/rive/view-model/snapshot.js:259-309` treats the whole current snapshot as changed when the baseline is empty.
- `src/app/ui/instantiation-controls-dialog.js:137-162` initializes selection from that changed snapshot.
- `src/app/platform/export/demo-export.js:52-78` uses the changed snapshot when no explicit selection exists.
- `src/app/platform/export/web-instantiation.js:140-203` correctly emits only the snapshot/keys it receives.

Required closure: establish the authored-value baseline only after the authoritative child has published the complete ViewModel hierarchy and values; re-baseline after source/artboard/instance reset; keep explicit user selection independent. Add a desktop cold-load test proving a zero-change file yields initialization-only compact code and a one-control edit yields exactly one accessor.

### 3. MCP accepts a playback name that does not exist

**Severity: Medium — agentic correctness failure**

Live reproduction:

```text
rav_switch_artboard({ artboard: "LowerThird", playback: "anim:Definitely Missing" })
```

returned `applied: true`, and subsequent status echoed the nonexistent animation with null timing. An export then completed 30 frames but had only five distinct decoded frame hashes; frames 5–29 were repeats. The same fixture with the valid authored timeline `LowerThids-In` exported 60/60 distinct frames for exactly 1.0 second.

An invalid artboard name is correctly rejected, so this is limited to playback validation. The command currently trusts the canonical state echo, while the unit test only covers a child that leaves canonical playback unchanged.

Evidence:

- `src/app/platform/mcp/commands/status-playback.js:149-167`
- `tests/unit/platform/mcp-authoritative.test.js:312-319`

Required closure: validate the requested playback name and type against inspected artboard metadata before staging, reject unknown/mismatched targets, and require a runtime first-frame/timing confirmation. Add a real dual-WebView regression test for the echo-invalid-name path.

### 4. A WebKit WebGL context loss can deadlock file activation beyond the JavaScript deadline

**Severity: Medium — intermittent resilience risk**

One TrackMap open reached native `opened_file.read_complete` but never activated. The UI stayed at Loading, MCP timed out, and accessibility actions returned `AXError.cannotComplete`. A process sample showed WebKit's main thread blocked in:

```text
WebGL2RenderingContext.useProgram
RemoteGraphicsContextGLProxy::getProgrami
forceLostContext
internal lock wait
```

The existing JavaScript load deadline covers awaited phases in `src/app/platform/render-surface/controller/load-operation.js:39-150`, but it cannot execute when the WebKit main thread itself is blocked. Four subsequent cold-start repetitions passed, so this is not deterministic.

Evidence artifacts:

- `/Users/ivg/Library/Application Support/app.rive.animation.viewer.flicker-test/rav-operations/session-1788486868428-37112-1136c537-5e9c-45aa-813a-b545d78828f5.jsonl`
- `/tmp/com.apple.WebKit.WebContent_2026-09-03_220105_whVp.sample.txt`

Required closure: add a host/native watchdog outside the WebView that can destroy and recreate a child which has not confirmed activation by the deadline, retry once, and log the recovery outcome.

### 5. The standalone media harness writes an unignored nested Cargo target into source

**Severity: Medium — repository hygiene and disk risk**

Running the documented standalone harness creates:

```text
src-tauri/src/app/media_export/tests/target
```

During this audit it contained 1,627 files and occupied 150 MB. The root `.gitignore` ignores `src-tauri/target` and `src-tauri/target-*`, but not this nested target, so every harness build appears as untracked repository content.

Evidence: `.gitignore:7-16`.

Required closure: give the harness an external/shared Cargo target directory or add a precise ignore entry, and include a test/CI assertion that a harness run does not dirty the repository.

### 6. Strict native linting is not clean

**Severity: Low — maintenance gate**

`cargo clippy --all-targets -- -D warnings` fails with 14 warnings promoted to errors. The set includes unused media re-exports/imports, dead helpers, two excessive-argument warnings, clone-to-slice, needless returns, and manual multiple checks. Runtime tests still pass; the project does not currently enforce Clippy as a release gate.

Required closure: either fix/scope the warnings or document and enforce the intended lint policy before calling the native quality gate clean.

### 7. Linux-only GTK dependency advisory remains informational for this macOS build

**Severity: Informational**

`cargo audit` found no vulnerabilities. It reports the unsound advisory RUSTSEC-2024-0429 for `glib 0.18.5` plus unmaintained GTK3-related packages. Dependency tracing places this in the Linux GTK/WebKit branch of Tauri/Wry, not the macOS runtime exercised here. Track it for Linux support and upstream Tauri/Wry upgrades.

## Release acceptance gates

Do not release 2.5.5 until all of the following are true:

1. Production encoder distribution is licensed, packaged, hash-verified, signed/notarized, and validated without developer tools installed.
2. A cold-load compact snippet contains no accessor unless that control was explicitly selected or actually changed; one selected property yields exactly one path.
3. Unknown playback names fail closed before export or capture.
4. The host recovers from a wedged/lost child WebGL context without requiring an app restart.
5. The standalone harness leaves no unignored Cargo output in source.
6. A fresh production desktop build passes the full automated suite and the same real-fixture format, timeline, state-machine interaction, UI, and MCP matrix.
