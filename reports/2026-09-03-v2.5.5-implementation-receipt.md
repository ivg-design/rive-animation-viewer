## Implemented

Independent metadata inspection owns copied bytes and its own runtime file. It returns plain metadata and releases its resources; the live player is not used to enumerate `contents`. Source/runtime/artboard/VM/session guards cover snapshots and queued mutations. Canonical selection now rejects an old file's updates while a replacement loads.

The desktop clock has explicit advance/draw/flush and a native wake-up for hidden windows. Stale RAF timestamps cannot send negative time. Reset waits for actual rendered frames, including a bounded timer fallback. Image restoration fences are captured after decode, and decoded references are released even when assignment fails.

Export uses a separate explicitly advanced player, including preroll before a segment. Its canvas has a real hidden layout box: Rive's ResizeObserver otherwise marks detached canvases zero-sized and advances time without drawing. Zero-size draws fail. Capture dimensions preserve aspect/layout, and only animation pixels plus an optional cursor are encoded.

The native job service validates inputs, bounds queues/disk/processes, supervises encoders without a shell, validates decoded output and atomically publishes. Legitimate WebKit eXIf metadata is sanitized without parsing before PNG decoding. Explicit FFmpeg and optional gifski adapters support bounded GIF attempts.

The existing desktop Export menu now includes media modes alongside standalone HTML/snippets. UI and MCP share options/jobs; typed mouse injection reaches Rive's actual mouse listeners, with pointer id 0. Multi-touch injection is not advertised. Eight new MCP tools bring both registries to 57; native string errors remain errors.

## Corrections found during desktop QA

1. Initial WebKit frame was rejected because it contained eXIf: added CRC-checked ancillary-metadata sanitization.
2. Hidden fallback and old RAF timestamps could disagree: clamp stale timestamps and preserve one advancement owner.
3. Detached export canvas reported advancing frames while drawing nothing: sized hidden canvas plus fail-closed draw receipt; verified distinct pixels and segment equivalence.
4. Synthetic PointerEvents did not reach Rive's mouse handlers: dispatch compatibility MouseEvents and verify actual runtime pointer calls.
5. Native errors rejected as strings could become null success replies: normalize error text before transport.
6. Focused linked dimensions could retain stale numbers: preserve only actual in-progress edits, not an untouched focused peer.
7. Replacing LowerThird with TrackMap during capture exposed stale canonical selection writes: source/runtime/session guard added; built desktop retest passed.
8. An MCP open immediately after launch could race startup discovery of `Latest`: runtime loading now awaits shared, idempotent discovery before choosing its cache key. A delayed-discovery regression test confirms early loads wait and use the discovered runtime.

## User-reported regressions and historical b0197 retest

These findings qualify the earlier successful smoke checks. Control counts and
rendered sectors did not prove the enum dropdowns were populated. The b0197
recording rows also predate the exclusive fixed-step clock; they are retained to
show the diagnosed failure and are not the final recording acceptance evidence.

- **Enum options:** reproduced on the earlier build with six live/canonical
  `viewMode` choices but only `(no enum values)` in the host select. The initial
  UI was built before its live accessor was available; subsequent synchronization
  updated the selection but not the options. Options now synchronize independently
  of value/topology changes. Late metadata also survives canonical deltas and
  coalesced acknowledgements. No VM values are reset or inferred from the first option.
- **Centered capture:** before the fix, a 922×754 preview became 922×518.625 at
  top=0 during output-sized capture. The capture-only flex container centers it
  at top=117.6875 and restores its original geometry afterward.
- **Recording cost:** a real five-second 1080p/60 baseline received only 101 of
  300 frames. Synchronous PNG encoding cost about 22 ms and a serialized ACK
  another 17 ms. Three overlapping slots with `toBlob` improved this to 222/300,
  but WebKit still compressed for about 20 ms on the animation thread. Worker PNG
  compression removes that stall; transferred bitmap copy remains on the draw path.
- **Result presentation:** only EXPORT opens results. STOP remains available
  during recording. Completed jobs leave no extra toolbar button. Overlapping
  capture/presentation hold messages become one amber quality summary, calculated
  from output count minus received captures; genuine errors remain errors.
